# youdomae-main

## Cloudflare Pages and D1

Posts and accounts are stored in D1 through the Pages Function API in `functions/api`. The Pages project already has the D1 binding named `DB`.

1. In **Workers & Pages → your Pages project → Settings → Variables and Secrets**, add `ADMIN_PASSWORD` as a secret. Set it to the existing administrator password. It is only used to create the first administrator record in D1; later logins are checked against the salted password hash stored in D1.
2. Apply the latest `schema.sql` to the same D1 database bound as `DB`. In the D1 dashboard, open that database's **Console**, paste the full contents of `schema.sql`, and run it. Alternatively, run `npx wrangler d1 execute <DATABASE_NAME> --remote --file=./schema.sql`. This creates the posts, accounts, sessions, featured-post, and advertising rate-limit tables if they do not exist.
3. Deploy the project as a Cloudflare Pages project with Functions enabled. The static page and the `functions/` directory must be deployed together.
4. To deploy automatically on every push to `main`, add GitHub Actions repository secrets named `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. The workflow in `.github/workflows/pages-deployment.yml` deploys the repository root and Pages Functions to the existing `youdomae-main` Pages project. Create a Cloudflare API token with **Account → Cloudflare Pages → Edit** permission; add the token and account ID directly in GitHub **Settings → Secrets and variables → Actions**. Never put either value in source code.
5. For automatic banner-ad inquiry emails, create a Resend API key and verify a sending domain in Resend. In the Pages production environment's **Settings → Variables and Secrets**, add `RESEND_API_KEY` as a secret and `ADS_FROM_EMAIL` as a variable using an address on the verified domain. Inquiry messages are sent to `keaji1614@gmail.com`; the submitter's address is set as the reply-to address. The endpoint limits each IP to one inquiry every 10 minutes and does not store inquiry contents in D1.

The page imports posts already saved in the current browser into D1 when it first connects. Posts, photos, comments, and like counts are then shared with visitors to the same deployment. The highest-liked post is pinned for 24 hours at a time; when its timer expires, the next-highest eligible post is featured. New account registrations, administrator credentials, and expiring login sessions are stored in D1; passwords use salted PBKDF2 hashes and session tokens are stored as hashes. On the administrator's first login after deployment, the existing administrator account is created in D1 and assigned the admin role. If the API reports missing D1 tables, run the full current `schema.sql` against the database bound to the Pages production environment. Photos are limited to 1.2 MB after compression to fit D1 row limits. Videos remain in the author's browser; sharing video files requires an R2 bucket and is not configured here. Accounts previously registered only in a browser are not migrated.
